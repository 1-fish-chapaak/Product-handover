Three principles, distilled from the feedback

Cause and cost leadAn insight’s first line is what broke, why, and what it costs — not a description of what happened. The root cause moves from the detail view to the teaser (Kapil 2), and observation + stakes merge into one story since each is meaningless without the other (Deepanshu 1–2).
Numbers carry contextNever a bare count. Every figure travels with its share of the population and its weight against materiality (Deepanshu 3) — within the honesty rules we already wrote: no percentage under a population of 20, no trend on one run, unsized stays visibly unsized.
Triage, then read, then act — each one stepFailed first, ranked by severity × impact, passes folded away (Deepanshu 4). Filters appear when volume needs them (Deepak 2). Acting lands you on the result, with the machinery folded behind it (Deepak 3, Kapil 4).

The prompt, restructured — the card read aloud, ending in a TL;DR

The PRD already fixes the seven parts of an insight card: title · what we found · likely root cause · what’s at stake · evidence · recommended action · severity. The auditor has read that structure on every card — so the prompt reuses it instead of inventing a new one. Three labelled blocks in a fixed order, one idea per pointer, machinery evicted to the Plan tab, and a three-sentence TL;DR at the end. Nothing new to learn: if you can read the card, you can read the prompt.

Today — what auto-send lands on~450 words of machine prose: action, rationale, methodology, taxonomy, scope and instruction interleaved — then the plan rendered twice more and seven assumptions before any result.

TL;DR— (new)Do · Because · Mine — three sentences, ≤ 40 words, derived mechanically from the blocks above.
  • One idea per pointer — a pointer that wraps twice is two pointers. Fixed block order every time, so the second prompt reads in half the time of the first.
  • What got evicted, and to where: priority/category taxonomy, methodology basis, full scope note and the assumption list move to the Plan tab and assumptions panel the workspace already renders — the prompt stops duplicating them. The plan renders once, never twice.
  • The skeleton is action-agnostic: the same three blocks serve all six PRD action types (email the insight · drill deeper · recommend control/risk · add to report · workflow frequency · missing control/workflow) — only WHAT TO DO’s verbs change. On surfaces that carry a rec without its card (grouped panels, RACM popover), WHY shrinks to the anchor line and the TL;DR still forms.
  • Implementation is one function: composePrompt() in actionRun.ts already holds every field this template needs — this is a reorder + rewrite of that function, no new data.

The honesty rules these designs inherit

Showing impact as percentages makes it easier to accidentally print a lie, so the KPI band enforces the qualification criteria we already wrote:

Share claimsA % renders only when the population is ≥ 20 — below that, the tile shows “X of Y” counts. (70/90 → 78% is legal; 1 of 3 never becomes “33%”.)
Materiality% of the engagement’s materiality floor. When the total isn’t firm, the tile says est. with “size before sign-off” — an unsized stake is a visible state, not a hidden one.
TrendsDelta chips (↑12 vs June) require 2+ runs; one-run insights show no delta and keep the “early signal” label.
CauseAlways “likely cause — confirm before relying on it”, in the teaser and the lead block alike. Promotion to the front doesn’t promote it to a fact.
